# 性能优化前后对比（连接复用 + 预编译语句缓存）

- 日期：2026-09-11 · 同机同参对比 · 工具：tests/benchmark.py
- 优化点：每工作线程复用 SQLite 连接（原每请求 open+PRAGMA+close）；按 SQL 文本的预处理语句 LRU 缓存（上限 32/连接，消除重复 prepare）

## 结论

- **读路径收益最大**：并发 20 时吞吐 451→3155 rps（+599.5%），p50 由 41.71ms 降至 5.73ms（-86.3%）。原每请求 open+PRAGMA+close 的固定开销在读短事务中占比极高，连接复用后该开销消失；
- **写路径同样受益**：diff-slot 各档吞吐 +10%~+47%；same-slot 争抢档（写锁串行化为瓶颈）吞吐 +31%，p50 -32.6%（写瓶颈在锁而非连接时收益收窄，符合预期）；
- E2/same-slot c=5 的 p50 波动为小样本（16 轮）下的正常抖动，吞吐口径-2.1% 在噪声范围内；
- 该对比验证了"读多写少的校务场景下，连接/语句复用是第一优先级优化"的判断。

注：吞吐提升幅度随并发上升而增大（读路径），说明原固定开销在并发下被放大（每请求都要重复付出），消除后高并发收益最明显。
