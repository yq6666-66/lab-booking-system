# 答辩现场演示脚本（约 8 分钟）

> 前置：演示服务已运行（`powershell -File scripts/start-demo.ps1 -Password 'Demo-Lab-2026'`），
> 浏览器打开 http://127.0.0.1:8080 ，另开一个无痕窗口或第二浏览器作为第二用户。
> 演示账号：admin / user01 / user02 / user03（密码均为 Demo-Lab-2026）。

## 0. 开场铺垫（30 秒）
- 展示登录页：说明 C11 + CivetWeb + SQLite 单文件后端，浏览器零依赖前端。
- 以 admin 登录 → 右上角显示"管理员"。

## 1. 发布容量制场次（1 分钟）
- 管理工作台 → 新增实验室"答辩演示实验室"→ 保存。
- 发布开放场次：实验室选"答辩演示实验室"，日期今天~今天，**容量填 2**，发布。
- 切到"预约实验室"标签：选该实验室 → 指出每个场次卡显示"已约 0/2"（容量制实时计数）。

## 2. 预约与满员（1 分钟）
- admin 点击第一场（08:00）"立即预约" → 刷新后显示"已约 1/2 · 我的预约"。
- （讲台话术） second 浏览器以 user01 登录 → 预约同场次 → "已约 2/2"。
- 回 admin 视角刷新：第一场显示"已满"。

## 3. 撞满 → 替代时段 → 候补（2 分钟，核心亮点）
- admin 视角保持停留在"已满"的旧页面（不要刷新），直接点击"立即预约"：
  → 服务端判定满员，返回 409 + **替代时段面板**（同实验室 7 天内空闲场次）。
- 点击面板中任一场次 → 一键改约成功（说明：提交时服务端重新校验）。
- 讲解：这就是"预约失败后的服务端引导"，替代列表与 SQL 对账一致。

## 4. 取消 → FIFO 自动补位（1.5 分钟）
- admin 在"我的记录"取消刚才的预约 → 刷新：名额自动流转给候补者（屏幕可见状态变化）。
- 指出审计日志：操作事件记录了 CANCEL 与 PROMOTE，且二者在同一事务内。

## 5. 签到与爽约（1.5 分钟，讲机制为主）
- 说明：签到窗口 15 分钟（可配 1 秒），超时由服务端扫描线程在**单个事务内**回收+补位+通知。
- 展示测试证据页（TEST_REPORT）：三类故障注入各 10 轮全部正确——
  未提交崩溃整体回滚、提交后崩溃结果持久、扫描崩溃原子恢复。
- （可选）user02 打开通知面板：候补补位通知已读/未读。

## 6. 管理统计与运行指标（1 分钟）
- 管理工作台 → 预约统计：按日聚合，导出 CSV（Excel 直接打开，含 BOM 与合计行）。
- 运行指标面板：请求计数、状态分类、延迟直方图——进程内存态，重启清零。

## 7. 收尾（30 秒）
- 回到测试报告页：720 次并发争抢零超卖、20 次崩溃恢复全部正确、
  单元 20 + 集成 31 + 模糊 240 + 覆盖率 84%~98%。
- 一句话收束："全部结论来自可重复执行的自动化实验，脚本与原始证据均在仓库内。"

## 应急预案
- 若某页面异常：F5 刷新（前端会话保持）；若服务异常：`start-demo.ps1 -Reset` 30 秒内重置整个演示环境。
- 网络演示全部走 127.0.0.1，不依赖外网。
