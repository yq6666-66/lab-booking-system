# 答辩现场演示脚本（约 9 分钟）

> 前置：演示服务已运行，浏览器打开 http://127.0.0.1:8080 ，另开一个无痕窗口或第二浏览器作为第二用户。
> 演示账号：admin / user01 / user02 / user03（密码均为 Demo-Lab-2026）。
> 登录页分「用户登录」与「管理员登录」双入口；管理员登录后自动跳转独立控制台 /admin.html。

## 0. 前置准备与开场铺垫（1 分钟）
- （可选，赛前准备）重建带 10 天历史的演示库，让统计图表与全员记录现场就有真实内容：
  `LAB_SEED_PASSWORD='Demo-Lab-2026' ./build/lab-booking.exe --db data/demo.db --seed --demo-days 10 --init-only`
  再启动：`./build/lab-booking.exe --db data/demo.db --port 8080`（若 demo.db 已带历史数据可跳过重建直接启动）。
- 展示登录页：说明 C11 + CivetWeb + SQLite 单文件后端，浏览器零依赖前端；指出双入口设计。
- 以管理员入口登录 → 自动跳转管理控制台，右上角显示"admin · 管理员"。

## 1. 发布容量制场次（1 分钟）
- 控制台 → 实验室管理 → 新增实验室"答辩演示实验室"→ 保存。
- 场次发布：实验室选"答辩演示实验室"，日期今天~今天，**容量填 2**，发布。
- 场次管理：指出每个场次卡显示"已约 0/2"（容量制实时计数）。

## 2. 预约与满员（1 分钟）
- 回用户端（返回用户端链接），admin 在"预约实验室"点第一场（08:00）"立即预约" → 刷新后显示"已约 1/2 · 我的预约"。
- 第二浏览器以 user01 登录 → 预约同场次 → "已约 2/2"。
- 回 admin 视角刷新：第一场显示"已满"。

## 3. 撞满 → 替代时段 → 候补（1.5 分钟，核心亮点）
- admin 视角保持停留在"已满"的旧页面（不要刷新），直接点击"立即预约"：
  → 服务端判定满员，返回 409 + **替代时段面板**（同实验室 7 天内空闲场次）。
- 点击面板中任一场次 → 一键改约成功（说明：提交时服务端重新校验，且与本人既有场次做时间重叠检测 BR11）。
- 讲解：这就是"预约失败后的服务端引导"，替代列表与 SQL 对账一致。

## 4. 取消 → FIFO 自动补位（1 分钟）
- admin 在"我的记录"取消刚才的预约（页内两段式确认）→ 刷新：名额自动流转给候补者。
- 指出审计日志：操作事件记录了 CANCEL 与 PROMOTE，且二者在同一事务内。

## 5. 知情候补与三档策略（2 分钟，r25–r26 创新点）
- **知情候补**：user02 找一个已满场次点"加入候补"→ 按钮上直接显示"历史转正率约 X%"，
  成功提示显示"当前排第 N 位，历史转正概率约 X%"——数据来自同实验室同星期过去 5 周释放分布的经验统计（样本不足时诚实显示样本不足）。
- **三档策略讲解**（指着按钮讲，不必现场切实例）：候补递补支持 strict / executable（默认）/ weighted 三档，
  weighted 把操作系统调度 的老化思想迁移过来：score = 1000×优先级 + 200×信用 + 60×log₂(等待)。
- **（可选，+40 秒）weighted 实测演示**：赛前另起一个加权策略实例
  `copy data\demo.db data\demo-w.db && build\lab-booking.exe --db data/demo-w.db --port 8081 --waitlist-strategy weighted`
  user01/user02 各候补一场 → 用一行命令把 user01 的入队时间拨到 10 小时前：
  `python -c "import sqlite3;c=sqlite3.connect('data/demo-w.db');c.execute(\"UPDATE waitlist SET created_at=strftime('%s','now')-36000 WHERE user_id=(SELECT id FROM users WHERE username='user01')\");c.commit()"`
  admin 取消占用者 → 名额给 user01（久等者反超）而非 id 序更靠前的后者——aging 生效。
- **对照数据**（口头给结论）：三策略×四档负载实验：strict 在队首冲突时空置率 100%，executable/weighted 均满额递补且 weighted 平均等待减半（7.2ks→3.6ks），Jain 公平指数三档一致——证据在 docs/evidence/experiment/。

## 6. 签到实操与爽约机制（1 分钟）
- **实操**：user01 切到用户端「签到」Tab → 今日场次卡片显示"待签到" → 点击签到 → 变为"已签到 ✓"。
- 机制讲解：签到窗口可配，超时由服务端扫描线程在**单个事务内**回收 + 补位 + 双向通知（BR5/BR6）；30 次故障注入恢复全部正确。

## 7. 管理员控制台走查（1.5 分钟）
- 「用户管理」：前缀搜索、分页；"近 7 天爽约"列——演示数据里有 6 个用户显示红色「受限中」标记（BR10）。
- **「公平性审计」**（r26）：统计页底部 Jain 公平指数表——按用户列出候补入队/转正/退出/平均等待秒，
  顶部指数 1 为完全公平；说明这是候补治理的量化工具（每用户转正率与被跳过次数一目了然）。
- 「资源管理」：切换实验室查看设备清单（状态三态），**现场新增一台"答辩演示示波器（维修中）"** → 切用户端预约页立即可见资源 chips（一体化卖点）。
- 「统计与导出」：SVG 双系列趋势图（10 天真实数据）+ 资源利用率表 → 一键导出 CSV（含 BOM 与合计行）。
- （如时间允许）「运行日志」：级别筛选 ERROR 检索真实访问日志。

  计时旁路实验响应时间比 1.07（显著降低账号枚举可观测差异）、覆盖率 83%~98%、三策略矩阵与位图算法对比实验。

## 应急预案
- 若某页面异常：F5 刷新（前端会话保持）；若服务异常：`powershell -File scripts/start-demo.ps1 -Password 'Demo-Lab-2026'` 重启，
  或用第 0 节命令 30 秒内重建整个演示环境（--demo-days 10 一键恢复全部历史数据）。

- 网络演示全部走 127.0.0.1，不依赖外网。
